# Google Acquisition Quality V3.1 — production-safe zero-result handling

## Production evidence
Master execution **2696**, collector **2697** (2026-11-07 ~14:29 IST) used the correct Account 2 credential. The Google query generated by V3 was:
`"WordPress" ("looking for" OR "need a developer" OR "hire a freelancer" OR "seeking a developer") -tutorial -guide -course -certification`.
SerpApi returned a structured, successful Google response, but 0 results with:
- `search_metadata.id` populated and `search_metadata.status: "Success"`
- `search_information.total_results: 0`
- `search_information.organic_results_state: "Fully empty"`
- `error: "Google hasn't returned any results for this query."`
- No `organic_results` array

V3 incorrectly treated any `response.error` as a provider failure and the recovery circuit recorded code **503** (source `google`), invoking a 15-minute cooldown. This was **not a proven 503 from SerpApi**.

## V3.1 changes (collector draft, not active until explicit publication)
1. Relax `Google Source Enabled` query generation. Recognized service/topic becomes short plain-text search, e.g. `WordPress developer needed`, `WordPress backup recovery developer needed`, `WooCommerce checkout fix developer needed`. Remove exact quoted OR chains and blanket keyword exclusions that caused zero results. Original `search_query` remains unchanged for audit and profile query cursor; preserve explicit `site:` constraints and fallback for unknown topics.
2. In `Annotate SerpApi Response With Lease`, recognize **only** a verified empty-results envelope: status Success, valid search ID, total_results=0, and the known Google fully-empty indicator and/or exact known no-results message. Reject arbitrary API errors, quota responses, HTTP >=400, malformed metadata, or failed lease conditions.
3. For verified empty result, normalize `organic_results: []`. The existing `Validate Source Domain` -> `Split Out` chain then produces 0 Google candidates; the response is treated as successful search, never sent through provider failure RPC. Do not manufacture candidate rows.
4. Keep original account-specific SerpApi circuit, recovery lease, one-query probe, low Google traffic strategy, prefilter, AI classification and service/budget gate unchanged.
